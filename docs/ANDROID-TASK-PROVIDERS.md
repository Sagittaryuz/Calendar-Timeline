# Integrações de tarefas — revisão 0.6, configuração pendente

A entrega utilizável permanece a 0.5.0-debug, no commit `374a354`. Esta revisão acrescenta código de integração e telas de conexão, mas **não declara contas externas conectadas nem suporte validado de ponta a ponta**. Nenhum cliente OAuth, token, conta, segredo ou permissão de conta foi criado no desenvolvimento. As flags de configuração estão desativadas por padrão.

## Dados e consistência

Identidade canônica inclui provedor, conta, lista e ID de tarefa. Títulos iguais não causam fusão. Samsung via To Do conserva a identidade Microsoft e não ganha uma segunda cópia. O Graph pode trocar o ID ao mover uma tarefa de lista; um snapshot completo das listas escolhidas remove a entrada antiga e recebe a nova.

`TaskApi` pagina as listas/tarefas em endpoints oficiais fixos e recusa redirecionamentos ou continuações fora do recurso/host. Token não vai a URLs arbitrárias. Google consulta concluídas, ocultas, excluídas e atribuídas explicitamente. O snapshot é aplicado somente após sucesso de todas as páginas/listas; falha preserva os dados e `syncedAt`. Exclusões/ausências removem entradas no próximo snapshot completo. Limites: 1.000 páginas, 10.000 itens e cache privado de aproximadamente 3,5 milhões de bytes UTF-8; exceder preserva o snapshot anterior com erro. Esta revisão usa snapshot completo; [Graph delta](https://learn.microsoft.com/en-us/graph/api/todotask-delta?view=graph-rest-1.0) foi avaliado, sem implementação incremental anunciada.

O JSON original guarda campos de origem, hierarquia, status, ETag e recorrência sem normalização destrutiva. Tarefas sem data permanecem na coleção de fontes, fora do calendário/widget. Datas Google são civis e sem horário. Graph mantém datas/alertas separados no JSON; a projeção usa vencimento, ou alerta se não houver vencimento. Fuso desconhecido não é convertido silenciosamente para UTC. Recorrência externa não passa pelo mecanismo local e tarefas externas não podem ser arrastadas/copiadas para o armazenamento local.

Concluir/reabrir pede versão atual e envia somente PATCH de status com ETag. Mudança concorrente ou HTTP 412 exige sincronizar; falta de ETag bloqueia a escrita. O comportamento de `If-Match` de cada serviço ainda exige teste real. Séries Graph são bloqueadas para preservar a origem. Não há fila de escrita offline, repetição automática ou confirmação otimista. Se a origem aceitar uma alteração e a leitura seguinte falhar, a mensagem informa alteração remota com cache pendente. Uma nova consulta verifica versão antes de qualquer repetição.

As listas escolhidas e uma geração de conexão impedem aplicar uma resposta antiga após desconectar/autorizar novamente. Cada nova requisição também confere a conexão/sessão; desconectar interrompe as próximas páginas, sem esperar na fila de sincronização. Uma requisição já em voo pode terminar, mas não repõe o cache desconectado. Desconectar remove o cache da conta e a sessão em memória; tenta também revogar/limpar pelo SDK oficial, sem prometer revogação no serviço se a rede falhar. Os acessos podem ser revistos nas configurações Google/Microsoft. Nada é apagado da origem.

## Consentimento e configuração necessária

Não foi encontrado cliente OAuth configurado nos arquivos do projeto, nas propriedades locais/Gradle ou nas variáveis de ambiente relevantes. Isso não consulta nem exclui a existência de registros nas contas cloud do proprietário. Foram solicitados os nomes/IDs públicos dos projetos/registros a usar. O responsável precisa autorizar especificamente qual projeto/registro será usado antes de habilitar os provedores. Não se deve fornecer segredo ou token ao agente ou colá-lo na interface.

**Google:** usar ou registrar um cliente Android oficial e habilitar Tasks API no projeto aprovado; revisar branding, política de privacidade, audiência/testadores e eventual verificação. Pacote `com.sagittaryuz.calendartimeline`, SHA-1 público do certificado debug existente `9D:96:B4:97:ED:4C:20:17:14:F4:ED:B9:31:19:66:69:C7:99:34:EA`. A flag de build `-PcalendarGoogleOAuthConfigured=true` só deve ser usada depois de confirmar esse registro. Nenhum servidor, client secret, refresh token próprio ou OAuth web é necessário para o caminho local implementado. O usuário escolhe a conta no seletor oficial e consente `https://www.googleapis.com/auth/tasks.readonly`; somente ao escolher conclusão solicita-se `https://www.googleapis.com/auth/tasks`.

**Microsoft:** cliente público Entra aprovado, com contas pessoais/organizacionais conforme a audiência escolhida pelo responsável. Fornecer somente o ID público em `-PcalendarMicrosoftClientId=UUID_APROVADO`. Registrar o redirect do pacote/certificado existente: `msauth://com.sagittaryuz.calendartimeline/nZa0l%2B1MIBcU9O25MRlmaceZNOo%3D`. O manifest usa o path decodificado correspondente. Fluxo MSAL/browser com PKCE, broker desativado, sem client secret. O app solicita escopo delegado `Tasks.Read`, ou `Tasks.ReadWrite` apenas se a pessoa escolher conclusão. Não solicita `Tasks.ReadWrite.All`, `User.Read`, contatos ou acesso a outras pessoas. O SDK pode incluir os escopos OIDC necessários ao próprio login e gerir seu cache após consentimento; isso ainda precisa ser conferido na tela real. Nenhum login foi executado nesta etapa.

Após configuração: validar seleção de conta correta, consentimento parcial/recusa, revogação, expiração, recuperação de processo, rotação durante OAuth, conclusão/conflito, recorrência, mudança/exclusão de lista, conta pessoal/organizacional e Samsung real. Não classificar a integração como pronta antes disso. A sessão de API desta prévia fica em memória; após expiração/reinício é preciso reconectar pela tela de fontes. Renovação silenciosa após recuperação de processo e atualização remota por job permanecem pendentes; o widget continua usando o cache privado. Abrir o calendário sincroniza sessões válidas com intervalo mínimo de cinco minutos; escolher listas sincroniza imediatamente.

## Outros protocolos avaliados

[CalDAV RFC 4791](https://www.rfc-editor.org/info/rfc4791/) e [VTODO RFC 5545](https://www.rfc-editor.org/info/rfc5545/) são caminhos para servidores que anunciem VTODO em `supported-calendar-component-set`. Uma implementação futura precisa descobrir principal/home/coleções, selecionar coleções, preservar UID/RECURRENCE-ID/RRULE/VALARM, ETags, exclusões e conflitos. Nem todo servidor CalDAV oferece tarefas; isso não equivale a compatibilidade universal nem acesso aos Lembretes modernos do iCloud. Credencial/app password e servidor exigiriam consentimento específico; nenhum foi configurado. Cliente CalDAV ainda não implementado.

O [OpenTasks público](https://github.com/dmfs/opentasks) oferece outro caminho local mediante contrato e permissões próprios; não dá acesso aos bancos privados Google/Samsung. Não foi acrescentada permissão customizada nem integração não validada. Apps sem API/ponte documentada precisam de avaliação individual; não se lê tela, banco privado ou notificações como substituto de consentimento.

Cache de tarefas/tokens não entra no backup exportado nem no backup Android.

As capturas da revisão usam somente tarefas sintéticas e indicam configuração pendente. O APK 0.5 da Library não foi substituído pela prévia de provedores. Código, build e testes sintéticos são entregáveis de revisão; a configuração OAuth continua pendente de autorização específica do responsável e o uso de cada conta depende de consentimento no aparelho.
